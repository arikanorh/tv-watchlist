# tv-watchlist

Personal TradingView-style watchlist: one static `index.html` (vanilla JS, no build, no backend) with live quotes, a TradingView chart widget and multiple watchlists. Goal: reach several lists quickly, see how each is doing (sentiment %), open a symbol's chart when needed. Live at https://arikanorh.github.io/tv-watchlist/ and https://tv-watchlist.pages.dev (both serve `main`). Owner: arikanorh (personal GitHub, not the work GHE).

Read `DATA-SOURCES.md` for the exact protocols (websocket framing, scanner payloads, widget postMessage API, BOATS overnight, chart websocket, field catalog) and `README.md` for the feature/data-channel overview.

## Runtime architecture (index.html)

**State** — `state` in `localStorage` key `tvwl.state.v2`: `{ activeListId, interval, symbol, view, sort, chartHidden, listHidden, ownChart, chartOpts, legsCollapsed, theme, flags, migrated[], lists:[{id, name, summary, groups:[{name, collapsed, symbols[]}]}] }`. `summary` is `true` (average of the list's equities), a symbol string (TR → `BIST:XU100`) or `false`. `seed()` builds the default lists; `load()` runs `SYMBOL_FIXES` / `REMOVED`, one-time migrations recorded in `migrated`, drops keys of the previous design (pinned, details, history), and `ensureEarnings()` keeps the **Earnings** list (`auto: 'earnings'`, a list already named Earnings is adopted) last with two groups: "Upcoming" (`auto`, rebuilt by `updateEarnings()` after each quote batch from every other list's symbols whose `earnings_release_next_date` is 0–7 days away, sorted by day; rows can't be moved/removed/dragged; never synced) "Manual" (the user's own; the Add row and "Add to list" put symbols there, which then leave Upcoming) and, last, "Reported" (`auto: 'reported'`, shown only when non-empty: symbols whose last report (`lastEarnings`) is within the past 2 days, newest first; Upcoming excludes them). `lastEarnings` is `earnings_release_date`, or a scheduled `earnings_release_next_date` that has passed (at once when the timing is known, else after 12 h) — TradingView rolls the pair late and a fresh quote session can return the stale pair, so without this a reporter would drop out of both sections; such rows get a neutral "results not in yet" badge (`resultsPending`). Results come from `earnResult` (EPS / revenue actual vs forecast from the quote fields `earnings_per_share_fq`, `earnings_per_share_forecast_fq`, `revenue_fq`, `revenue_forecast_fq`): rows of recent reporters get a green (beat) / red (miss) "E" badge (`.erep`, 2 days), details gets a "Last earnings" section, and the chart's last-report E is colored the same with a hover popover of the numbers (shown whenever its bar is loaded; the next-report popover shows the estimates). The list can't be deleted or reordered; new lists go before it. Bumping `KEY` would reset everyone's lists.

**Layout** — mobile first. Phone: one pane at a time (`body[data-view]` = `list` / `chart`) behind a two-tab nav (Liste / Grafik). What you read is at the top, what you tap at the bottom:
- Header `.top` (session-tinted: pre amber, open green, post blue, overnight purple): list name + sentiment % on the list pane, symbol + last + chg% on the chart pane (tap → search); then the pins. The session label / last tick time + status dot block (`#hr`, tap → reconnect) shows only on desktop with the chart hidden.
- List pane: table (Symbol / Last / Chg% / Ext; Ext hidden during the regular session via `body.regular`), collapsible groups, then the dock: one chip per list — `listTag`: an icon (`l.icon`, else `LIST_ICON_BY_ID`: abd → US flag, inci → pearl, tr → TR flag, krip → Bitcoin, zorning → eye; the Earnings list a calendar), a leading emoji of the name, else two letters; full name as tooltip — with its sentiment % (on desktop the dock is a compact 46px tab row right above the list, under the sentiment chart: `.lblock { order: -2 }`, `.dock { order: -1 }`, % as "+0.7" without the % sign) (tap → switch; the row scrolls sideways, the mouse wheel scrolls it too), `⋯` (list manager) and `⚙` (settings: sync box, version, reconnect); every list ends with an add row (`.addrow`: "+ Add Symbol" → search in add mode, "+ Add Section" → `addSection`, a new group at the end; not on the Earnings list; both half width); the Chg% and Ext column headers toggle the sort (`state.sort` = `chg` / `ext` / null).
- Chart pane: TradingView widget and its toolbar `.ctools` = interval segmented control (`#seg`) + chart bar (`Search`, `ⓘ` details). Phones: under the chart, intervals above the search row. Desktop: the search box (symbol, last, chg%: `#cbSym/#cbPx/#cbChg`) and the full interval segmented control float over the chart's top-left corner (`.cover`, moved there by `placeTools`); the toolbar row above the chart (50px, session-tinted) holds the pinned quick symbols (`PINS`: US100, SPX, US10Y, VIX, BTC, ETH — two lines, left-aligned: name, then last (no decimals from 1,000) + chg%; click → chart; always subscribed via `allSymbols`; on phones `placeTools` moves `#pins` into the header right of the list name — the same two-line cells, smaller, scrollable if tight; the session/clock block `#hr` is hidden on phones, the tint tells the session and reconnect is in Settings); the `ⓘ` details button is phone-only. The header's `#hr` block (session label, tick time + version, chart-hide button) is not shown on desktop while the chart is visible (the toolbar's session tint is the cue; the hide-chart button sits at the toolbar's far right and a round tab `.ltab` on the seam between the list and the toolbar (fixed at 368px, 6px when hidden) hides/shows the watchlist (`state.listHidden`, `body.list-hidden`: the list column collapses to 0); never both hidden); it appears in the full-width header when the chart is hidden (`placeTools` keeps it in `.top`).
- Details (`detailsHtml`): today range, open, prev close, volume vs average; 52-week range, 1W / 52W / from-ATH; valuation (market cap, P/E, EPS, P/S, P/B, dividend yield, beta); company (sector, industry, country, revenue, net margin, next earnings, analyst target); then **News** (`newsHtml`: the symbol's latest 25 TradingView headlines — source, age, "breaking"; tap → summary inline via the story endpoint and a link to the original; cached 2 min; direct on localhost, via the relay's `/news` and `/news/story` elsewhere). Phones: a bottom sheet (`toggleDetails`), also from the row menu. Desktop: a 300px column between list and chart (`state.detailsOpen`). Re-rendered on every quote batch.
- Phone chart bar (`.ctools`, <768px): one row — search, an interval dropdown (`#ivBtn` → `openIntervalPicker` sheet), details; no segmented intervals or theme switch. The search sheet hangs from the top on phones (`.sheet.top`, set in `openSheet`) with the field first, so the iOS keyboard can't cover it; `trackKeyboard` also runs on `visualViewport` scroll.
- ≥768px: `body` becomes a grid: the list pane (380px) fills the full height on the left, topped by `.lblock`: the sentiment chart `#sent` with the list head (`.lhead`: list name + sentiment %) floating over its top-left corner, above the table; the header `.top` is hidden (its contents live in the chart toolbar) unless the chart is hidden, when it spans the full width above the list; details (optional) | chart fill the rest; `.main` is `display: contents`; the dock's list chips render as underlined tabs (name + sentiment %) on desktop; nav hidden; header button hides the chart (`state.chartHidden`).
- Sentiment chart (desktop only, `renderSentiment`): a plain line of the active list's sentiment % over time (green above zero, red below, dashed zero line when in range), with US100 and SPX500 as faint muted benchmark lines on the same scale (`BENCH`, sampled into `hist['@<symbol>']`; the tooltip lists them too), from `hist` (`tvwl.hist.v1`; `sampleHistory` every 15 s while open, 2 h at full rate, thinned to 1/min, 24 h kept), y axis scaled to the range's min/max (labels placed on the side away from the extreme). Clicking the chart cycles the range shown top-right: Today/Overnight (current session from `sessionOpenTs`: 04:00 or 20:00 ET) → 1h → 4h → 24h; opens on the session every load; hover shows time and value.

**Interactions** — one delegated `click` handler on `document` dispatches on `data-act`. Rows: tap → `selectSymbol()` (chart; phones switch to the chart pane; the already-selected symbol is a no-op apart from the view switch). Press and hold 420 ms (a mouse drags right away after 8px) → the row lifts: release in place → actions sheet (`openRowMenu`: details, flag, add to another list (`openCopySheet`; the symbol stays here too), add section above (`addSection({gi, i})`: the row and those below it move into the new group), move up / move down within the group (hidden in sorted view), remove from the list — asks first: the option arms on the first tap ("Remove X? Tap again"), the inline ✕ arms for 3 s — then an undo toast; removals stack (`undoable`/`undoStack`): "CRWV removed (+2 more) · Undo 3", each Undo takes back the latest, cleared 8 s after the last removal); drag → reorder within/between groups (pointer events on `#rows`, a non-passive `touchmove` stops scrolling once lifted). Desktop: hovering a row shows the flag strip `.fl` (the 8px left border itself, no icon; each click cycles the color, `cycleFlag`); right-click opens a context menu at the pointer (`openRowCtx`: details, Flag ▸ colors, Add to list ▸ lists, add section above, move, remove with a second click), and the keyboard: ↑/↓ walk the visible rows and update the chart, ←/→ switch watchlists (ignored while a sheet or input has focus); any letter opens search with it typed; digits 1–8 open the interval picker (`openIntervalPicker`) and, while it is open, pick the interval. Sorted view (`state.sort` = `chg` or `ext`): non-equities stay on top as "Index", the rest is one "By change" / "By ext" group by that column; drag and the inline up/down are off. Sheets (`openSheet`/`closeSheet`) are bottom sheets on phones and centered dialogs on desktop: row actions, add-to-list, interval, search (`openSearch(addMode)`, input at the bottom on phones; ↑/↓ move the highlight, Enter picks it, even while results load; from the list's "Add symbol" row Enter/tap adds to the active list and stays, from the chart it only opens the chart; each result's `+` adds in both), list manager (`openListManager`: rename, ↑/↓, Σ sentiment on/off, delete with a second tap, new list), settings (`openSettings`: sync box, theme segmented control, own-chart toggle, version, reconnect).

**Chart** — `CHART_ALIAS` charts an equivalent feed for symbols the embed won't chart (`TVC:US10Y` → `PYTH:US10Y`, `TVC:VIX` → `CAPITALCOM:VIX`; aliased symbols are exempt from `noChart`; `TVC:TNX`, `FRED:*`, CME/CBOT futures show "only available on TradingView"). TradingView Advanced Chart free widget (`mountChart()`), toolbars/legend/volume off, `sessionId: '24h'`. Symbol and interval changes go through the undocumented iframe postMessage API (`send('set-symbol'|'set-interval')`), so the chart never reloads; messages queue until the iframe's first message (`chart.ready`). A widget mounted while its pane has no size stays blank, so `chart.hiddenAtMount` triggers a remount when the pane shows (`setView`, resize). The free widget cannot chart BIST or plain indices (`noChart()`): those symbols open **our own chart** instead (`showOwnChart` / `#ownChart` over the widget in `.charea`): history and live bars from TradingView's chart websocket (`chart_create_session` / `resolve_symbol` with the chart option "Session" (`regular` / `extended` / `24h` — the latter adds the overnight Blue Ocean bars for US stocks, others fall back to `extended`; default `24h`) / `create_series`, 300 bars, unauthorized token — BIST is delayed; direct on localhost, via the relay elsewhere; one session per request, replies matched by session id), drawn with Lightweight Charts 4.2 loaded from unpkg on first use (its logo is off; our icon sits bottom-left and switches to the TradingView widget, a "TV" box in the same spot over the widget switches back — both flip `state.ownChart`; the attribution link is in Settings). Re-requesting the same series (same symbol / interval / session, `own.dataKey` — i.e. after a socket drop) keeps the bars and the view counted back from the last bar (`own.keep`) instead of blanking and `ownFitView`. When a live bar opens while the last bar is in view the client shifts the range by the bars added (the future axis already holds that slot, so the library wouldn't). A request that gets no bars in 8 s closes the chart socket (watchdog; onclose reconnects and re-requests). A spinner (`#cload`, `ownBusy`) sits at the plot's top-right, just left of the price axis, while bars load; right of the search box a market-status dot and a details-panel toggle (`.cinfo`, accent when open); the market-status dot (`#mkt`, colored by `sessionPhase`; click → `openMarketPop`: the US day as a bar with ET/local times, a now marker and "next session in …"; closes on outside click/Esc). Scrolling near the oldest bar loads 300 more (`ownMaybeMore` → `request_more_data`, 300 ms debounce; older bars are merged and the series reset with the view kept in place; an empty answer stops further requests). Mouse wheel zooms like TradingView (the right edge stays put, so the right margin keeps its size in bars; bar count changes, capped at what fits at `minBarSpacing` 0.1 — past that the library clamps the spacing itself and pushes the last bar left; sideways wheel pans; the library's own wheel handling is off). Intraday bars are shifted to local time; our own last-price label (`ownCountdown`, `.plabel`: price, day change %, bar-close countdown for minute intervals, in one box; the library's label is off) sits on the price axis; the ⚙ in the bottom-right corner where the axes meet (`openChartOpts`: on desktop a context-style checklist menu `.cmenu` beside the gear — or at the pointer on right-click over the own chart — that stays open while toggling, with "Session" as a flyout submenu to the left (hover or click; picking a session closes the menu), closes on outside click/Esc; a sheet on phones; `CHART_OPTS`/`setChartOpt`) toggles the % and countdown lines, the session shading, the volume histogram (`own.vol`, bottom fifth, candle-colored, chart option "Volume"; also toggled from the TradingView-style legend under the ticker panel, `#legs`/`ownVolLegend`: rows Vol, SMA 20, SMA 50, SMA 200, High / Low (visible range) with the hovered bar's values; a chevron collapses the legend, `state.legsCollapsed`, else the latest, click toggles), SMA 20 / SMA 50 / SMA 200 lines (`SMAS`, `ownSma`, amber/blue/pink, default off), the visible-range high/low markers (`ownHiLo`, `.hilo`/`.hm`: our own triangle + price pill above the highest and below the lowest bar in view, repositioned with every countdown/range tick; chart option "Visible high / low") (`ownSessions`, `.sessbg`: pre/post/overnight tints behind the bars for US symbols on minute intervals, phases from ET bar times; `state.chartOpts`, local). `setChartInterval` re-requests the series while the own chart is active. Desktop: a tool column on the own chart's left (`.ctool`, `CHART_TOOLS`, 40px; the chart and its overlays shift by `--tb`): **Measure** (button or Shift + click: click to start, move, click to end; box from A to B stored as bar index + price so it sticks to the chart, label with Δprice (Δ%), bars + time span, volume in between; blue up / red down; a plain click on the chart (box or empty space), Esc or the bin clears it — `initMeasure`/`ownMeasure`), then toggles for Volume, SMA 20, SMA 50, SMA 200, High/Low, Earnings (`ownEarnings`: hover shows the date plus the timing — `earnTiming` from `earnings_release_next_time`: 1 after close, -1 before open, 0 not given; the last report shows its actual ET time; an "E" on the time line at `earnings_release_date` — filled, on its bar, only for a day after the report — and `earnings_release_next_date` — outlined, in the empty space after the last bar, placed by counting bars of the interval/session with `sessionBarsUntil`; hover = date; when the next report is within 7 days the first view (`ownFitView`) already reaches it), and future dates on the time axis (`ownFuture`: whitespace points on a hidden series after the last bar, stepped by interval and session via `futureTimes`, rebuilt when a new bar opens), session shading, countdown, change % (`paintTools` mirrors `chartOpts`). **Horizontal ray** (tool button, or "Horizontal ray at <price>" at the top of the chart's right-click menu, desktop): a click draws a line from that bar to the right edge at that price (`initRays`/`ownRays`, `.hrays`/`.hray` DOM overlay with a price tag on the axis; stored in `state.lines[sym] = [{id, t, p, k?, d?, hit?, at?, ack?}]`, `t` = bar time (local-shifted like the bars) so it shows on every interval from the bar containing `t`); drag moves it (the start handle goes to the pointer's bar + price; the line body moves as a whole, start time included — a start older than the loaded bars only moves in price), click selects (start handle), Delete/Backspace or right-click → "Remove line" deletes (undo). **Alerts** ride on these lines: `k` = `alert` (amber; fires once when the price crosses it — `d` is the crossing, +1 up / −1 down, set by `armRay` from the live price whenever the level is created, moved, edited or re-typed — then goes passive: dashed), `buy` / `sell` (green / red; their B / S icon stays next to the ticker, colored while the price is in the zone; reaching one fires a note once). Set from the line's right-click menu (kinds, Re-arm, "All alerts of …") or the Alerts sheet (`openAlerts`, row menu → Alerts on desktop and phone: type / price per level, remove, add — lines added there start at the latest bar). `checkAlerts()` runs on every quote batch against `livePrice` (the row's Last, extended outside regular hours; symbols with alerts are added to the quote subscription in `allSymbols`); any open device can fire and the `hit` syncs. Row icons: `alertIcons` (`.alr`: B / S plain outline, filled green / red only while the live price is at or below a buy point / at or above a sell point, bell muted while armed → amber ringing once fired until its note is dismissed). Notes (`renderNotes`, `#notes`, fixed under the top bar, two at a time + "+N more" / "Dismiss all"): fired alerts / reached points not yet dismissed (`ack`) and fresh earnings results of listed symbols (last 2 days, results in, not in `state.seen`); click opens the symbol, ✕ dismisses (synced). A note that appears after the first 15 s chimes (`chime`, WebAudio unlocked on the first pointerdown) and, when the page is hidden and permission was granted (`askNotify` on first alert), posts a system notification. Settings has "Own chart for all symbols" (`state.ownChart`, local): `useOwn()` routes every symbol to our chart and `mountChart` skips the widget.

**Quotes** — `raw[sym]` holds merged websocket fields; `quotes[sym] = {p, c, e, ep, ss}` (last, chg%, extended chg%, extended price, session dot). Sources:
1. Websocket: direct on localhost, `RELAY_WS` elsewhere (TradingView accepts the handshake only from allow-listed origins). Subscribed set = every symbol of every list (`allSymbols()`), so all chips show live sentiment. Watchdog: 30 s without any `qsd` while the socket is open → reconnect (the session can go silent while heartbeats continue).
2. Overnight (20:00–04:00 ET): `wsSync()` also subscribes each US stock's `BOATS:<ticker>` twin; `onQuote` takes the overnight price from it and computes the change against the regular close. Dropped when the phase ends (`renderSession`).
3. If the socket never opens → `quoteSource = 'poll'`: scanner REST every 10 s, hidden mini widgets (`syncFeeders`, max 4) for symbols the scanner lacks. `?quotes=poll` forces it.
`renderQuotes()` (throttled 250 ms) patches cells in place with flash, refreshes chips and header; in sorted view it re-orders at most every 3 s and never under a finger or an open sheet. Outside regular hours Last shows the extended price and Ext the extended change with a colored dot (amber pre, blue post, purple overnight). Prices: 2 decimals ≥ 1, T/B above a billion, 4 significant digits below 1 (`fmtPrice`). Earnings within 7 days show a tag next to the ticker; a moon / sun (after close / before open) joins it only when the report falls in the current session (`earnsThisSession`: today's trading day, or the next one from 20:00 ET / at weekends).

**Sync across devices** — the lists (`syncShape`: id, name, summary, auto flag, groups with name and symbols — the Earnings list's auto group is left out) live in the relay worker, one `SyncRoom` Durable Object per code (codes stored in KV before v1.8 are copied into the room on first use), under a code of 4–12 letters/digits (random ones are 4 characters without I, O, 0, 1 and checked to be unused; the user can type their own; 12-character codes from v1.3–1.5 still work) (`GET/PUT /state/<code>`). The room also tracks devices: each client sends a stable id (`tvwl.client` in localStorage) and a UA label (`SYNC_NAME`, e.g. "iPhone · app") as `?client=`/`?name=` on the websocket and PUT URLs; the worker stores `devices` (id → name, last seen; 90 days) and broadcasts `{type:'peers', live, devices}` on connect/close, shown in the sync box (`devicesHtml`: live count, device list). `state.flags` (symbol → color name; TradingView-style flags drawn as the row's 8px colored left border (`.row.flagged`; the selected row no longer has an accent border), set from the row menu / inline flag tool via `openFlagSheet`; `FLAGS` has the six colors) travels with the doc too; the worker stores every field beyond `updatedAt`/`lists` and, when a PUT from an older client lacks one, keeps the stored value, so old and new versions can share a code (clients ignore fields they don't know and only adopt `flags` when present). The list sort (`state.sort`: Chg% / Ext / own order), chart lines / alerts (`state.lines`) and dismissed earnings notes (`state.seen`: symbol → release time) are synced as doc fields too. Per-device things stay local: active list, symbol, view, interval, collapsed groups, history. `save()` → `syncNoteChange()` stamps `state.sync.updatedAt` when the synced shape changed and pushes 0.5 s later. Live updates: `syncConnect()` holds a websocket to the code's room (`/sync/<code>?client=<id>`); the room sends its copy on connect and after every save from another device (`syncReceive`: newer → adopt, older → push ours; waits while a row is pressed). Keep-alive ping/pong every 30 s, reconnect with backoff, reconnect + `syncPull()` on resume; the 60 s poll only runs without a live socket. The worker answers 409 to an older PUT. Sync box (settings sheet `openSettings`, not the list manager): off = one code field (prefilled with the last code or a random suggestion) + Turn on (`useSyncCode`: a code in use replaces this device's lists, a free one starts with them); on = code + Copy + Turn off. To change the code: turn off, edit, turn on. When a pull brings in another device's edits, `showSyncNote` shows a 6 s note under the header with the symbols added/removed per list (`syncDiff`); using a code explicitly skips it. `#sync=CODE` in the URL opens settings with the code filled in. iOS home-screen apps have their own storage, so enter the code inside the app. `?sync_api=http://localhost:8788` points the client at a local `wrangler dev` for testing.

**Client log** — `clog(kind, msg, data)` keeps a ring buffer (socket open/close/stalls, chart loads with timing, chart timeouts and errors, window errors, unhandled rejections) and posts it to the sync room (`POST /log/<code>`, text/plain, sendBeacon on pagehide; only while sync is on). Read a device family's log with `curl https://tv-watchlist-relay.tv-watchlist.workers.dev/log/<CODE>` (`?since=<ms>`, `DELETE` clears); entries carry client id, device name and app version. The worker keeps the last 1,500 entries for 7 days. A claude.ai cloud routine ("tv-watchlist daily log digest", trigger `trig_01G6GPo67EW3kvDySGwdh8ru`, daily 06:00 UTC) reads the last 24 h for code A1234 and analyses it (errors, reconnect loops, stalls, chart load p50/p95 per device/version). It stays silent when all is well; when it finds a clear bug on the current version it is meant to fix it, bump `APP_VERSION`, push `main` and notify "Released vX.Y — fixed …" (needs the repo attached to the routine — a GitHub account connected in claude.ai); otherwise it pushes a short issue digest.

**Themes** — `THEMES` (dark, light; a segmented moon/sun control at the toolbar's right on desktop (the version label stays rightmost), in Settings on phones; `[data-theme-seg]`, `paintTheme`) are variable overrides on `html[data-theme]` (`applyTheme`, `state.theme`, local); session tints, cover and grid are variables too (`--sess-*`, `--cover`, `--grid`). Both charts read the variables: the own chart via `ownTheme()`/`cssVar`, the widget at mount (`theme`, `backgroundColor`, `gridColor`), so a theme change remounts it.

**PWA / iOS** — `fitStandalone()` drops the nav's home-indicator padding when iOS stops the web view short of the screen (`body.ios-gap`); `unshift()` snaps the document back after keyboard use (otherwise taps land off target); `trackKeyboard()` keeps bottom sheets above the keyboard (`--kb`).

**Tab title** — `renderHeader` sets `document.title` to the chart symbol and its chg%, plus the extended-hours chg% outside regular hours (e.g. `CRWV -15.46% · ext +0.80%`).

**Versioning** — `APP_VERSION` shows in the nav (phones) and at the right end of the chart toolbar (desktop, `#tver`; also in the header when the chart is hidden); bump it on every push to `main`. Off localhost the page re-fetches itself on load and on resume and reloads when the live version differs. On localhost/LAN it live-reloads on file change.

## Vocabulary

The owner calls a watchlist's aggregate move **sentiment**: *sentiment yüzdesi* = the list's day % (`listValue`, from `summarySymbols`: equities only, TR → XU100, Krip → USDT pairs only; outside regular hours it uses the extended move); *sentiment grafiği* = its history chart (`renderSentiment`, desktop only). The per-symbol *sentiment bar'ı* of earlier versions is not in 1.0.

## Constraints and decisions

- Single file, no framework, no backend, no build step.
- Mobile first; information at the top, interaction at the bottom.
- Nothing may depend on the user's logged-in TradingView account. Only on an explicit "listeleri güncelle" request: read `GET /api/v1/symbols_list/custom/` from a TradingView tab the user opened, snapshot to `reference/`, update `seed()`.
- The chart widget is official; the websocket, scanner, symbol search and iframe postMessage API are reverse-engineered and may break without notice. Keep the polling fallback working.
- Replies to the user in Turkish with English technical terms; terse progress updates.
